# Roo Code 规则

## 1. 适用范围

- 本文件只约束 Code 模式。
- 当任务属于源代码增删改、实现、自测、证据整理时，必须在 Code 模式下执行。
- 当任务属于需求澄清、方案设计、任务拆解、门禁裁判、规则修订时，必须交由 Architect 模式执行。

## 2. 启动判定

- 开始任何任务前，先判断当前角色是否应为 Code。
- 若用户请求的是实现、修复、重构源码、补丁操作、执行自测，保持 Code。
- 若缺少 Architect 任务执行包，必须停止，不得自行实现。
- Code 必须只按 `doc/Architect/code-task-package-需求后缀.md` 执行。
- 若缺少需求编号、需求后缀、任务编号、目标文件、操作类型，必须停止并请求补充。

## 3. 规则来源

- 最高优先级来源为 [`doc/ai-coding-collaboration.md`](doc/ai-coding-collaboration.md)。
- Architect 任务执行包为 Code 执行的直接依据。
- 旧版说明仅作历史参考，不得覆盖当前规则。

## 4. Code 输出要求

Code 必须输出以下文档，且必须使用需求后缀：

- `doc/Code/requirement-trace-matrix-需求后缀.md`
- `doc/Code/interface-trace-matrix-需求后缀.md`
- `doc/Code/test-item-trace-matrix-需求后缀.md`
- `doc/Code/defect-trace-matrix-需求后缀.md`

## 5. 文档写入规则

- 所有输出必须写入 `doc/Code/`。
- 所有输出必须是可复用 Markdown 文档。
- 所有文档必须包含 `适用规则: AI协作规则`。
- 所有文档必须包含 `后续工作传递声明`。
- 所有文档文件名必须采用 `文档类型-需求后缀.md`。
- 同一需求内的需求后缀必须一致。
- Code 输出的需求后缀必须与 Architect 任务执行包一致。
- 所有内容必须落盘，禁止只在对话中给结论。

## 6. 源码修改规则

- Code 对源代码新增、删除、修改前，必须确认任务编号存在于 Architect 任务执行包。
- Code 对源代码新增、删除、修改前，必须确认目标文件存在于 Architect 任务执行包。
- Code 对源代码新增、删除、修改前，必须确认操作类型存在于 Architect 任务执行包。
- Code 对源代码新增、删除、修改时，必须使用 `encoding_tools/README.md` 描述的接口。
- Code 对源代码新增、删除、修改时，必须优先使用 `encoding_tools/encoding_safe_patch.py`。
- Code 禁止直接用普通编辑方式修改源代码。
- 无法使用 `encoding_tools/` 时必须停止执行并记录阻塞原因。

## 7. 证据规则

Code 必须记录以下证据：

- 修改接口
- 配置文件
- 执行报告
- 影响文件
- 自测结果

证据规则：

- 证据必须落盘到 `doc/Code/` 或任务执行包指定路径。
- 证据只能引用文件路径、命令、报告路径。
- 禁止只写自然语言描述作为证据。
- 修改源代码后必须同步更新 Code 矩阵文档。

## 8. 矩阵同步规则

- Code 输出的需求编号必须与 Architect 文档一致。
- Code 输出的接口编号必须与 Architect 文档一致。
- Code 不得新增 Architect 文档未声明的需求编号。
- Code 不得新增 Architect 文档未声明的接口编号。
- 测试项必须映射需求编号和任务编号。
- 缺陷必须映射需求编号和测试项编号。

## 9. 完成判定

- Code 只有在四类矩阵文档全部落盘后才算完成。
- Code 只有在源码修改证据完整后才算完成。
- Code 只有在自测结果落盘后才算完成。
- Code 不得裁判门禁。
- Code 完成后必须等待 Architect 裁判。

## 10. 自检清单

结束前必须自检：

- 是否存在 Architect 任务执行包
- 是否严格按任务执行包执行
- 是否使用 `encoding_tools/` 修改源码
- 是否输出全部 Code 文档
- 需求后缀是否一致
- 需求编号是否一致
- 接口编号是否一致
- 证据是否可追溯
- 自测结果是否落盘

## 11. 禁止事项

- 禁止自行扩展任务范围。
- 禁止裁判门禁。
- 禁止修改 `doc/Architect/` 下的文档。
- 禁止直接普通编辑源代码。
- 禁止在缺少任务编号、目标文件、操作类型时继续执行。
- 禁止删除 Architect 输出文档。
- 禁止未落盘直接声明完成。

## 12. 推荐执行顺序

1. 接收 Architect 任务执行包
2. 判断角色
3. 检查最小输入
4. 校验需求后缀
5. 校验任务编号、目标文件、操作类型
6. 使用 `encoding_tools/` 执行源码修改
7. 记录修改证据
8. 执行自测
9. 输出 Code 矩阵文档
10. 自检
11. 移交 Architect 裁判
